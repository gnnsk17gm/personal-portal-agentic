# ADR 0015: 自宅普段使い用「基本モード（3列正方形タイルUI）」とポートフォリオモードのデュアル構成

- **ステータス:** Accepted (採択)
- **決定日:** 2026-11-23
- **決定者:** Project Architect

## 1. コンテキスト (Context)
これまでのフェーズ（Spec 001〜016）では、採用ポートフォリオとしての技術実証（AIエージェント観測、RAGスコア可視化、MCPテストランナー等）を優先してUIを構築した。
しかし、日常の自宅用パーソナルポータルとして毎日快適に利用するには、情報密度が高すぎ、AI関連のメタ表示が普段使いのノイズとなる。
一方で、転職活動や技術デモの際には従来のポートフォリオ機能を即座に呼び出せる状態を維持したい。

## 2. 検討した選択肢 (Options Considered)
- **Option 1: ポートフォリオ用と自宅用で別リポジトリ・別アプリに分離する**
  - DBやテスト基盤が二重管理になり、保守コストが増大する。
- **Option 2: 同一アプリ内に「基本モード（デフォルト）」と「Portfolioモード」の切替機構を導入する**
  - Cookie ベースのモード状態管理により、Server Components と Client Components の双方で現在のモードを判定し、レイアウトとダッシュボード表示を切り替える。

## 3. 決定内容 (Decision)
**Option 2（Cookie によるデュアルモード切替 + 3列正方形タイルダッシュボード）を採用する。**

### 選定理由:
1. **既存資産・テスト（127件）の100%継承:**
   - バックエンドの Service 層や SQLite スキーマを変更せず、プレゼンテーション層（UI）のモード分岐のみで実現できるため、既存の品質保証がそのまま維持される。
2. **圧倒的な日常使いやすさ:**
   - デフォルトを「基本モード」とし、3列正方形のタイルUIと余白クリック遷移を採用することで、直感的で拡張性の高いホーム画面になる。
3. **ポートフォリオ機能のスマートな格納:**
   - 左サイドバー最下部の控えめなスイッチ1つで、いつでも従来の全機能（Agent Explorer, MCP Runner, RAG表示等）へ切り替えられる。

## 4. 結果とトレードオフ (Consequences)
- **メリット (Positive):**
  - 普段使いの快適さと、面接デモの即応性を単一アプリで両立できる。
  - タイルグリッド構造により、今後の個人用ミニアプリ追加が容易になる。
- **トレードオフ (Negative):**
  - ダッシュボードや各画面でモードに応じた表示分岐（Conditional Rendering）が増えるため、コンポーネントの責務分離を明確に保つ必要がある。
