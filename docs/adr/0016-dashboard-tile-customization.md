# ADR 0016: Cookie ベースのダッシュボードタイル編集（並び替え・削除・追加）アーキテクチャ

- **ステータス:** Accepted (採択)
- **決定日:** 2026-11-23
- **決定者:** Project Architect

## 1. コンテキスト (Context)
Spec 017 で自宅用「基本モード」の3列正方形タイルグリッドを構築した。
日常利用において、ユーザーの生活スタイルや機能拡張に合わせて「タイルの表示順序の変更」「不要タイルの非表示（削除）」「利用したいタイルの追加」を画面上から直感的に行えるようにする必要がある。

## 2. 検討した選択肢 (Options Considered)
- **Option 1: 外部 Drag & Drop ライブラリ（`@dnd-kit/core` 等）の導入 + DBテーブル保存**
  - リッチなドラッグ操作が可能だが、React 19 / Next.js 16 との依存関係競合リスクや、DBマイグレーション・単体テストの複雑化を招く。
- **Option 2: 編集モードトグル（←/→ 移動・削除・追加UI） + Cookie 配列永続化（外部依存ゼロ）**
  - 表示順をタイルID配列として Cookie に保存し、Server Component でSSR描画。編集モード時のみ移動・削除・追加コントロールを表示する。

## 3. 決定内容 (Decision)
**Option 2（外部依存ゼロの編集モードUI + Cookie 配列永続化）を採用する。**

### 選定理由:
1. **SSRとの完全な調和（画面チラつきゼロ）:**
   - `localStorage` と異なり Cookie は初回リクエスト時にサーバー側で読み取れるため、ユーザーのカスタム順序のまま一発でSSRできる。
2. **デバイス非依存の操作性とテスト容易性:**
   - ボタン操作（前へ/後ろへ移動、削除、追加）を基本とすることで、マウスでもタッチ画面でも確実に動作し、配列操作の純粋関数として Vitest で100%決定論的にテストできる。
3. **タイルレジストリによる拡張性:**
   - 利用可能なタイル定義をレジストリ（`TILE_REGISTRY`）として一元管理することで、今後新しい自宅用ミニ機能タイルを増やす際もレジストリに1件登録するだけで追加・削除の対象になる。

## 4. 結果とトレードオフ (Consequences)
- **メリット (Positive):**
  - DBスキーマや既存133テストに影響を与えず、高速かつ安全にカスタマイズ機能を提供できる。
- **トレードオフ (Negative):**
  - Cookie サイズ上限（4KB）の制約があるため、保存データはタイルIDの文字列配列のみに限定する。
