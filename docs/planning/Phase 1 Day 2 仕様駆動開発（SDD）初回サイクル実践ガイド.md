# **プロジェクト内ドキュメント管理ディレクトリ設計**

AI駆動開発（特に仕様駆動開発：SDD）では、**「人間向けの全体方針・記録」** と **「AIが直接読み込んで実装を行う仕様書」** の置き場所を明確に分離することが、コンテキストの局所化（不要なトークンの節約と誤動作防止）において極めて重要です。

## **1\. おすすめのディレクトリ構造**

プロジェクトルート（personal-portal-agentic/ 直下）に、以下のように **docs/** と **specs/** を分けて配置する構成を推奨します。

personal-portal-agentic/  
├── .antigravity/              \# エージェント用コンテキスト（Rules / Skills / Hooks）  
│  
├── docs/                      \# 【人間 & プロジェクト全体向け】背景・方針・意思決定ログ  
│   ├── planning/              \# ★ Geminiに出力してもらった全体計画書・ロードマップ  
│   │   └── ai-development-plan.md  
│   └── adr/                   \# Architecture Decision Records（技術選定・アーキテクチャ判断ログ）  
│       └── 0001-tech-stack.md  
│  
├── specs/                     \# 【AI実装指示用（SDD）】機能ごとの厳密な仕様書（SSOT）  
│   ├── templates/             \# 仕様書テンプレート  
│   │   └── feature-spec-template.md  
│   ├── active/                \# ★ 現在実装中（AIに読ませる対象）の仕様書  
│   │   └── 001-dashboard-skeleton.md  
│   └── completed/             \# 実装・テスト完了後にアーカイブする仕様書  
│  
├── src/                       \# Next.js アプリケーションコード  
└── AGENTS.md                  \# Next.js 公式のエージェント向け規約

## **2\. なぜ docs/ と specs/ を分けるのか？**

### **① AIエージェントの誤認・コンテキスト肥大化を防ぐ**

* **specs/**:  
  * エージェントに「この仕様書に従って実装して」と指示する際、ピンポイントで参照させる領域です。  
  * active/ と completed/ に分けることで、過去の実装と現在のタスクが混ざるのを防ぎます。  
* **docs/**:  
  * 開発全体のロードマップや技術選定理由など、背景知識です。  
  * 実装時に毎回全文をエージェントに読み込ませるとトークンを浪費し、指示がブレる原因になるため、必要な時だけ参照させます。

### **② 転職ポートフォリオとしての見栄え**

採用担当者や技術面接官がリポジトリを見た際、「全体設計ドキュメント（docs/）」と「仕様駆動開発のプロセス（specs/）」が整然と分かれていると、**「AIのコンテキスト制約を理解してリポジトリ設計ができるエンジニア」** として強い説得力を持ちます。

## **3\. 現状のドキュメントの具体的な配置先**

| ドキュメント | 配置先パス | 役割 |
| :---- | :---- | :---- |
| **全体計画書・ロードマップ** （Gemini出力の計画書） | docs/planning/ai-development-plan.md | プロジェクト全体のゴール、技術柱、転職アピール戦略の記録 |
| **仕様書マスターテンプレート** | specs/templates/feature-spec-template.md | 新機能を作る際にコピーして使う雛形 |
| **これから作る各機能の仕様書** | specs/active/xxx.md | 実装時にエージェントへ渡す単一の仕様書 |

## **4\. フォルダ作成コマンド**

ターミナルで personal-portal-agentic ディレクトリ内に移動し、以下のコマンドを実行するだけで一括作成できます。

mkdir \-p docs/planning docs/adr  
mkdir \-p specs/templates specs/active specs/completed
