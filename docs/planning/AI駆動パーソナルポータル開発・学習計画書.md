# **AI駆動パーソナルポータル開発 & コンテキストエンジニアリング習得ロードマップ**

本書は、Google Antigravity等の最先端AI開発環境を駆使して「自分の情報・タスク・ナレッジを一元管理するパーソナルポータル」を開発しながら、**転職活動で「本格的なAI駆動開発・エージェントオーケストレーションができるエンジニア」として圧倒的な差別化を図るための体系的学習・実践計画書**です。

## **1\. 転職で評価される「AI駆動開発」の再定義**

単に「AIにチャットでコードを書かせた」「Cursor/Copilotで補完させた」というレベルは、すでに採用市場において差別化になりません。評価されるのは「AIエージェントの特性を理解し、破綻させずに大規模・高品質なシステムを自律的に構築させる開発プロセスとアーキテクチャを設計できる能力」です。

| 観点 | 一般的なAI利用（差別化にならない） | 本プロジェクトが目指すレベル（強いアピール） |
| :---- | :---- | :---- |
| **指示方法** | 都度思いつきの自然言語チャット | \*\*仕様駆動開発（SDD）\*\*に基づく構造化ドキュメント（SSOT） |
| **文脈管理** | 履歴の長文流し込み（ハルシネーション頻発） | **Rules / Skills / Hooks** を用いた精密なコンテキスト制御 |
| **エージェント制御** | 単一AIとの往復 | **Main Agent \+ Subagent** の並行タスク分散と合議 |
| **品質保証** | 人手での目視確認・コピペ修正 | Browser-in-the-loop・自動テスト・Hooksによる静的検証 |
| **ポートフォリオ** | 完成したアプリの画面のみ | **設計書、ADR（意思決定ログ）、Agent運用ログを含むリポジトリ** |

## **3\. 体系的習得カリキュラム（4つの技術柱）**

### **① コンテキストエンジニアリング（Context Engineering）**

* **コンテキストの分離と局所化:** 不要なトークンを削ぎ落とし、エージェントの判断精度を高めるコンテキストウィンドウの最適化。  
* **階層化ルール設計:**  
  * Rules: コーディング規約、アーキテクチャ原則（常に守らせる不変ルール）。  
  * Skills: 「新規APIエンドポイント追加」「E2Eテスト作成」などの定石化された手順書。  
  * Hooks: コミット前や特定フェーズで自動実行される検証スクリプト。

### **② 仕様駆動開発（Spec-Driven Development: SDD）**

* **人間の役割を「コード書き」から「システムアーキテクト」へ転換:**  
  1. **要件定義（Requirements）:** ビジネスロジックと制約の明文化。  
  2. **アーキテクチャ設計（Design）:** ER図、APIスキーマ、ディレクトリ構成。  
  3. **タスク分解（Implementation Plan）:** エージェントが並行処理可能な独立ステップへの分割。  
  4. **検証仕様（Verification Spec）:** 何をもって完了とするかの判定基準（コマンド・テストケース）。

### **③ エージェントオーケストレーション（Agent Orchestration）**

* **Antigravity 2.0 のマルチエージェント運用:**  
  * フロントエンド実装、バックエンドAPI構築、テストコード作成を複数のSubagentに並行委託。  
  * Git Worktreeや独立ワークスペースを活用したコンフリクト防止策の実践。  
* **Browser-in-the-loop自動テスト:**  
  * エージェントがヘッドレスブラウザで自律的に画面動作確認・UIデバッグを行うフローの構築。

### **④ ツールエコシステムとプロトコル（MCP / Agentic Tools）**

* **Model Context Protocol (MCP):** エージェントが安全にカレンダー、DB、ファイルシステム、GitHub等へアクセスするための標準インターフェース実装。

## **4\. 開発フェーズと実装ロードマップ（全8週間プラン）**

\[Phase 1: 基礎 & SDD環境構築\] (Week 1-2)  
  └── Antigravity設定 (Rules/Skills/Hooks) / 基本ダッシュボード基盤構築  
         │  
\[Phase 2: データ統合 & Context Layer\] (Week 3-4)  
  └── MCPサーバー連携 / 知識DB (Vector DB) / コンテキスト自動注入設計  
         │  
\[Phase 3: 自律型エージェント機能\] (Week 5-6)  
  └── Subagent並行オーケストレーション / ブラウザ自動化 / 日次ブリーフィング  
         │  
\[Phase 4: プロダクション化 & 転職資産化\] (Week 7-8)  
  └── CI/CD・品質メトリクス / ADR整備 / 技術記事執筆 / 職歴書への落とし込み

### **Phase 1: 開発環境のセットアップとSDD基盤の確立（Week 1-2）**

**目標:** Antigravityのルールエンジンと仕様駆動開発の手法を固め、ポータルの最小骨格を作る。

1. **リポジトリ構成の整備:**  
   * .antigravity/ ディレクトリ配下に rules/, skills/, hooks/ を設定。  
   * specs/ ディレクトリで仕様書を管理するディレクトリ構造を策定。  
2. **テンプレートの策定:**  
   * spec-template.md: 要件、アーキテクチャ、依存関係、テスト条件を記述するフォーマット。  
   * plan-template.md: Antigravityが生成するImplementation Planの承認フォーマット。  
3. **ポータルの基本スケルトン作成:**  
   * 技術選定: Next.js (App Router), TypeScript, Tailwind CSS, SQLite/PostgreSQL (Prisma or Drizzle)。  
   * **実践:** 人間がコードを直接書くのではなく、仕様書を書き、Antigravityに実装させ、レビューするサイクルを徹底する。

### **Phase 2: データ統合基盤とコンテキスト設計（Week 3-4）**

**目標:** 「自分の全てを管理する」ためのデータ連携を行い、エージェントが迷わないContext設計を実装。

1. **外部サービス・MCP連携:**  
   * Google Calendar / Gmail / Notion / GitHub / ローカルMarkdownファイルと接続するMCPクライアント/サーバーの構築。  
2. **ナレッジ層の構築（Second Brain）:**  
   * メモや日報を保存し、ベクトル検索（pgvector等）で関連文脈を取り出せるRAG/コンテキスト取得パイプラインの構築。  
3. **コンテキスト最適化の実践:**  
   * エージェントに一度に全情報を渡すのではなく、タスクの種類に応じて必要な「文脈（Skills \+ 関連ドキュメント）」だけを動的にアセンブルするプロンプト/コンテキストマネージャーの実装。

### **Phase 3: 自律型パーソナルエージェント機能の実装（Week 5-6）**

**目標:** ポータル上で動く高度な自動化エージェント群を構築し、Subagentの並行制御を体得する。

1. **自律型機能の実装例:**  
   * **Morning Briefing Agent:** 毎朝、カレンダー予定、未完了タスク、GitHubのPR状況、重要メールを要約して優先度順に並べる。  
   * **Task Decomposition Agent:** 「〇〇の技術記事を書く」「転職活動の応募企業リスト作成」といった抽象的なゴールを具体的なサブタスクと期限に落とし込む。  
2. **Antigravity Subagentの並行活用:**  
   * メインエージェントが計画を立て、バックグラウンドのSubagent（UI担当、API担当、テスト担当）に並行指示を投げるワークフローの実験と定式化。  
3. **Browser AgentによるE2E自動テスト:**  
   * Antigravityのブラウザ操作機能を使い、UI変更時に自動でポータルの画面を巡回・テストするフローを構築。

### **Phase 4: プロダクション化と転職ポートフォリオへの昇華（Week 7-8）**

**目標:** 開発した成果を「採用担当者・エンジニアリングマネージャーが唸るポートフォリオ」に変換する。

1. **リポジトリのドキュメンテーション:**  
   * **Architecture Decision Records (ADR):** なぜその技術選定をしたのか、どうコンテキストエンジニアリングを適用したかの論理的記録。  
   * **SDD Walkthrough:** 「仕様書1枚からAntigravityがどうPRを作成したか」の実例ログ（コミットログ、差分レビュー記録）。  
2. **開発メトリクスの可視化:**  
   * 人間のコード記述行数 vs AI生成行数の比率。  
   * テスト自動化率、仕様書からの初手実装パス率などの定量的成果。  
3. **デプロイ & パブリック発信:**  
   * Cloud Run / Vercel へのデプロイ（CI/CDパイプライン含む）。  
   * Zenn / Qiita 等での技術記事公開（「Google Antigravityで挑む仕様駆動開発とコンテキスト設計の実践」）。

## **5\. 職務経歴書・面接でのアピール戦略（STAR法）**

面接官に伝えるべきトークスクリプトの骨子です。

* **Situation（背景・課題）:**  
  「生成AIを活用した開発が一般化する中、多くの開発現場ではプロンプトの属人化やハルシネーションによるコード品質低下が課題となっていました。そこで、最先端の仕様駆動開発（SDD）とコンテキストエンジニアリングを検証するため、個人管理ポータルの自律開発プロジェクトを立ち上げました。」  
* **Task（自身のミッション）:**  
  「人間の役割を『コード生成』から『仕様・制約のアーキテクト』へと移行させ、Google Antigravityを核としたマルチエージェント自律開発プロセスを設計・実証すること。」  
* **Action（取った行動・技術的工夫）:**  
  * 常時制約（Rules）、手順ノウハウ（Skills）、自動検証（Hooks）にコンテキストを構造化。  
  * 自然言語の曖昧さを排除した機械可読な仕様書（SDD）をSSOTとして定義。  
  * Main AgentからSubagent群へのタスク並行分散と、Browser-in-the-loopによる自律テストサイクルの確立。  
* **Result（結果・成果）:**  
  * 実装作業の大部分をエージェントに自律遂行させつつ、テスト合格率とコード整合性を維持。  
  * AI時代に求められる『AIを指揮するソフトウェアエンジニア』としての再現可能な開発方法論を体系化。

1. **ポータルの要求仕様のブレインストーミング:**

2. **開発用GitHubリポジトリの作成:**  
   * personal-portal-agentic 等のリポジトリを作成し、README.md に「SDDおよびコンテキストエンジニアリングの実験プロジェクトである」旨を明記。  
3. **.antigravity/ の骨格作成:**  
   * rules（TypeScript, Next.js, テスト方針などの基本原則）を1ファイル定義してみる。
