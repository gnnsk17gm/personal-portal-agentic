# Spec 021: 家計簿機能（Finance Tracker）の実装

* **ステータス:** Draft / Ready for Implementation
* **関連 ADR:** `docs/adr/0018-finance-module-and-recurring-snapshot.md`
* **対象ブランチ:** `feat/home-finance-tracker`（`main` から分岐）

## 1. 目的と概要

自宅での普段使いに最適化した、シンプルでストレスなく継続できる家計簿機能（`/finance`）を実装する。
外部有料 API への依存を排除し、SQLite + Drizzle ORM によるローカル永続化と、Next.js App Router（Server Components + Server Actions）による高速な操作体験を提供する。

※ 本 Spec では `/finance` 専用画面およびナビゲーション導線の実装を対象とし、ダッシュボード（`/`）の正方形タイル追加は別 Spec にて扱う。

## 2. 機能要件

### 2.1 ナビゲーション & UI 方針

* **ルート:** `/finance`
* **サイドバー導線:** 左サイドバーナビゲーションに `Finance`（`Wallet` または `Receipt` アイコン）を追加する。基本モード（`standard`）・ポートフォリオモード（`portfolio`）の両方で利用可能とする。
* **デザイン準拠:** `.antigravity/rules/10-technical-standards.md` に従い、ライトモード基調（白〜スレート系背景、明確なコントラスト、クリーンなカードレイアウト）で統一する。基本モード時は AI 関連の装飾・文言を一切表示しない。

### 2.2 データベース層（`src/db/schema.ts`, `src/db/index.ts`）

ADR 0018 に従い、以下の 3 テーブルおよび初期テーブル作成 SQL を追加する。

* `finance_transactions`（収支明細）
* `recurring_expenses`（固定費マスタ）
* `monthly_budgets`（月間総予算）

### 2.3 カテゴリ定義（`src/lib/finance-constants.ts`）

* **支出カテゴリ:** `食費`, `日用品`, `交通費`, `住居・光熱通信`, `趣味・娯楽`, `医療・健康`, `衣服・美容`, `交際費`, `その他`
* **収入カテゴリ:** `給与`, `賞与・副収入`, `臨時収入`, `その他`
* 各カテゴリに視認性の高いライトモード向けカラーバッジ定義を持たせる。

### 2.4 月次サマリー & 月間総予算管理

* **対象月ナビゲーション:** URL クエリパラメータ（`?month=YYYY-MM`、省略時は当月）により対象月を切り替え可能にする（前月 `<` / 今月へ戻る / 次月 `>`）。
* **サマリーカード（4指標）:**
  1. **今月の支出合計**（前月比の差額表示付き）
  2. **今月の収入合計**
  3. **今月の収支バランス**（収入 − 支出）
  4. **月間総予算の残額 & 消化率プログレスバー**（予算超過時は警告色表示）
* **月間総予算の設定:** 対象月の総予算（円）をインラインまたはコンパクトなフォームから設定・更新できる。未設定の月は直近過去月の予算額をデフォルト表示（継承）する。

### 2.5 クイック収支入力フォーム

* **種別タブ:** `支出`（デフォルト）/ `収入`
* **入力フィールド:**
  * 金額（必須・1円以上の整数）
  * カテゴリ（種別に応じたプリセット選択）
  * 日付（デフォルトは今日。`今日` / `昨日` のクイック選択ボタン付き）
  * メモ（任意・最大100文字）
* **操作性:** 保存完了後、入力フォームの金額・メモをリセットして連続入力しやすい状態を維持し、ページデータを即時再検証（`revalidatePath('/finance')`）する。

### 2.6 カテゴリ別支出内訳

* 対象月の支出をカテゴリごとに集計し、金額の降順でバー付きリスト表示する（金額・構成比 `%`）。
* カテゴリ行をクリックすると、下部の収支明細一覧がそのカテゴリでフィルタリングされ、再クリックまたは「フィルタ解除」で全件表示に戻る。

### 2.7 収支明細一覧・検索・編集・削除

* 対象月の明細を日付の降順（同日は登録順の降順）で表示する。
* 自動計上された固定費明細には `固定費` バッジを表示し、手動入力と区別できるようにする。
* **絞り込み・検索:**
  * 種別フィルタ（`すべて` / `支出` / `収入`）
  * カテゴリフィルタ
  * メモのキーワード検索（クライアント側即時フィルタまたはクエリ絞り込み）
* **編集・削除:**
  * 各明細行から金額・カテゴリ・日付・メモをインライン編集（または編集モード展開）して保存できる。
  * 各明細行の削除ボタンから明細を削除できる。

### 2.8 固定費・サブスクマスタ管理 & 自動計上エンジン

* **固定費マスタ CRUD（作成・編集・有効/停止・削除）:**
  * 名称（例: `家賃`, `Netflix`）、金額（円）、カテゴリ、毎月の計上日（1〜28日）を指定して登録できる。
  * 登録済みの固定費マスタは、**名称・金額・カテゴリ・計上日のすべてを編集可能**とする。
  * 各項目に **有効 / 停止（`isActive` トグル）** と **削除** 操作を提供する。
  * UI 上に「※ マスタの変更・停止・削除は翌月以降の自動計上に適用されます。すでに計上済みの過去・当月明細は維持されます」という案内を明記する。
* **当月オンデマンド自動計上（`ensureRecurringTransactionsForMonth`）:**
  * 対象月が **現在の実年月（`YYYY-MM`）と一致する場合のみ** 実行する（過去月・未来月では自動生成しない）。
  * `isActive = true` の全固定費マスタについて、当月分の明細が未生成であれば `finance_transactions` に実体レコードを作成する。
  * ユーザーが当月分の自動生成明細を個別に削除した場合に、リロードで勝手に復活しないよう、当月処理済み記録（または重複防止チェック）を適切に制御する。

## 3. アーキテクチャ & ファイル構成案

* `src/db/schema.ts`: `financeTransactions`, `recurringExpenses`, `monthlyBudgets` テーブル定義
* `src/db/index.ts`: テーブルおよびインデックス初期化処理の追加
* `src/lib/finance-constants.ts`: カテゴリ定義・カラーマッピング・バリデーション定数
* `src/lib/finance.ts`: 月次集計、予算継承計算、固定費オンデマンド生成ロジック
* `src/app/finance/actions.ts`: Server Actions（明細 CRUD、固定費マスタ CRUD、月間予算更新）
* `src/app/finance/page.tsx`: Server Component（初期データ取得・自動計上トリガー・レイアウト構築）
* `src/components/finance/`:
  * `FinanceSummaryCards.tsx`（サマリー4指標＋予算編集）
  * `QuickTransactionForm.tsx`（クイック収支入力フォーム）
  * `CategoryBreakdown.tsx`（カテゴリ別内訳＆フィルタ連動）
  * `TransactionList.tsx`（明細一覧・検索・インライン編集・削除）
  * `RecurringExpenseManager.tsx`（固定費マスタの追加・編集・停止・削除パネル）

## 4. 受け入れ基準（Acceptance Criteria）

1. 左サイドバーの `Finance` から `/finance` に遷移でき、エラーなく画面が表示されること。
2. 支出・収入の新規登録、インライン編集、削除が SQLite に永続化され、月次サマリー・予算残高・カテゴリ別内訳が即座に正しく再計算されること。
3. 固定費マスタを新規登録・編集・停止（OFF）・削除できること。
4. 固定費マスタの金額変更や停止を行った際、すでに計上済みの明細データは一切変更・削除されず、翌月以降の自動計上のみに反映されること。
5. 同一月内で `/finance` を複数回リロードしても、有効な固定費が二重計上されないこと。
6. `npm run verify`（ESLint + TypeScript `tsc --noEmit` + Vitest）がエラー 0 件でパスすること。

## 5. テスト計画（Vitest）

`src/lib/__tests__/finance.test.ts`（または既存テスト構成に準拠したテストファイル）を作成し、以下を自動検証する：

* 収支集計（支出合計・収入合計・収支バランス・前月比）の計算精度
* 月間予算の保存および未設定月への直近予算継承ロジック
* 固定費スナップショット自動生成の冪等性（複数回実行しても二重登録されないこと）
* 固定費マスタ編集・停止・削除後に過去/当月スナップショットが不変であり、別月（翌月相当）では新設定が適用または停止されること
* 過去月・未来月に対して自動生成が走らないこと
