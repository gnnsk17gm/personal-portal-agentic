# Spec 023: AMEX 利用明細 CSV インポート機能の実装

* **ステータス:** Draft / Ready for Implementation
* **関連 ADR:** `docs/adr/0018-finance-module-and-recurring-snapshot.md`
* **前提 Spec:** Spec 021
* **対象ブランチ:** `feat/home-amex-csv-import`（`main` から分岐）

## 1. 目的と概要

アメリカン・エキスプレス（AMEX）の会員サイトからダウンロードした利用明細 CSV を `/finance` 画面からアップロードし、プレビュー画面でカテゴリ指定・不要行除外・重複チェックを行ったうえで一括登録できる機能を実装する。
外部ライブラリや外部有料 API は追加せず、ブラウザ標準 API と既存の SQLite + Drizzle ORM で完結させる。

## 2. 機能要件

### 2.1 UI 導線とモーダル構成

* `/finance` 画面上部の月ナビゲーションバー（「固定費管理」ボタンの隣）に **`CSV取込`** ボタン（`Upload` アイコン）を配置する。
* クリックすると **AMEX CSV インポートモーダル** が開く（Esc キー・背景クリック・`×` ボタンで閉じられる）。
* モーダル内は以下の 2 ステップで遷移する：
  1. **ファイル選択ステップ:** `.csv` ファイルの選択（ドラッグ＆ドロップまたはファイル選択ボタン）。
  2. **プレビュー＆カテゴリ指定ステップ:** 解析結果の一覧テーブル、対象件数・合計金額サマリー、一括登録ボタン。

### 2.2 AMEX CSV パース仕様（`src/lib/amexCsvParser.ts`）

* **文字コード自動判別:**
  * ブラウザ側で `ArrayBuffer` を読み込み、UTF-8（BOM あり/なし）として厳密デコード（`new TextDecoder('utf-8', { fatal: true })`）を試み、失敗した場合は `shift_jis`（`new TextDecoder('shift_jis')`）でフォールバックする。
* **CSV フォーマット対応（RFC 4180 準拠）:**
  * 実際の AMEX ヘッダー列に対応：`ご利用日,データ処理日,ご利用内容,カード会員様名,会員番号 #,金額,海外通貨利用金額,換算レート`
  * `"1,308"` のような **ダブルクォーテーション囲み＋カンマ区切り数値** を正しく 1 フィールドとしてパースする。
* **データ正規化:**
  * **日付:** `YYYY/MM/DD`（例: `2026/11/20`）を内部標準の `YYYY-MM-DD`（`2026-11-20`）へ変換する。
  * **ご利用内容（メモ）:** 全角英数字・全角スペースが含まれるため、`String.prototype.normalize('NFKC')` を行ったうえで連続空白を半角スペース 1 つに整形し前後トリムする（例: `"Ａｐｐｌｅ ｉＴｕｎｅｓ Ｓｔｏｒｅ "` → `"Apple iTunes Store"`）。最大 100 文字で切り詰める。
  * **金額:** カンマを除去して整数値（円）に変換する。正の値は `expense`（支出）として扱う。

### 2.3 自動判定・スマート初期値

1. **引き落とし・マイナス金額行の自動除外:**
   * 金額が `0` 以下（口座振替による引き落としや返金）の行は、二重計上防止のため **初期状態でチェックを外し（`selected: false`）**、`引き落とし・返金（除外推奨）` バッジを表示する。
2. **重複明細の自動検知:**
   * 既存の `finance_transactions` と **「日付（`date`）・金額（`amount`）・正規化済みメモ（`note`）」** がすべて一致する行は、すでに登録済みとみなして **初期状態でチェックを外し（`selected: false`）**、`登録済み` バッジを表示する。
   * ※ 同一日に同じ店で同じ金額を 2 回使ったケース（CSV 内に同一内容が 2 行ある場合）は、既存 DB の件数を超える分まで重複扱いしないようカウントベースで判定する。
3. **カテゴリの自動推測（`inferExpenseCategory`）:**
   * **優先度 1（過去履歴学習）:** 既存の `finance_transactions` に同一の正規化済みメモが存在する場合、最も直近に登録されたカテゴリを自動セットする。
   * **優先度 2（キーワード辞書）:** 初回の加盟店名に対して、代表的なキーワードで初期カテゴリを推測する（例: `セブンイレブン` / `ファミリーマート` / `ローソン` / `スーパー` → `食費`、`Amazon` / `ドラッグストア` → `日用品`、`JR` / `Suica` / `ETC` / `タクシー` → `交通費`、`Apple` / `Netflix` / `Spotify` / `ユザワヤ` → `趣味・娯楽`、該当なし → `その他`）。

### 2.4 プレビュー画面の操作性

* 各行に **取り込みチェックボックス**、**日付**、**ご利用内容（メモ編集可）**、**金額**、**カテゴリ選択ドロップダウン**、**ステータスバッジ（新規 / 登録済み / 引き落とし・返金）** を表示する。
* ヘッダーに「選択中: ● 件 / 合計 ¥XX,XXX」をリアルタイム表示する。
* 「選択した ● 件を一括登録」ボタンを押すと Server Action で一括 `INSERT` し、完了メッセージ表示後にモーダルを閉じて `/finance` を再検証する。
* ※ 取り込んだ明細の日付が現在表示中の月と異なる場合（例: 先月分も含まれていた場合）、登録完了時にその旨を通知する（例: `12件を登録しました（2026-11分）`）。

## 3. アーキテクチャ & ファイル構成案

* `src/lib/amexCsvParser.ts`: RFC 4180 対応 CSV パーサー、Unicode NFKC 正規化、キーワードカテゴリ推測の純粋関数群。
* `src/lib/finance.ts`: 重複判定用の既存明細照会ヘルパー、および一括トランザクション登録関数の追加。
* `src/app/finance/actions.ts`: `previewAmexCsvAction`（DB 履歴照合＋重複判定）および `importAmexTransactionsAction`（一括登録 Server Action）の追加。
* `src/components/finance/AmexCsvImportModal.tsx`: ファイル選択（UTF-8 / Shift_JIS 自動デコード）・プレビューテーブル・カテゴリ変更・一括登録 UI（Client Component）。
* `src/app/finance/page.tsx`: ヘッダーナビゲーションへの「CSV取込」ボタンとモーダル配置。

## 4. 受け入れ基準（Acceptance Criteria）

1. AMEX 実明細形式（`"1,308"` などのカンマ付き金額、全角スペース・全角英数字を含むご利用内容、`YYYY/MM/DD` 日付）の CSV を文字化けなくパースできること。
2. プレビュー画面で各行のカテゴリとメモを個別に変更し、チェックを入れた行だけを SQLite に一括登録できること。
3. 金額がマイナスの行（口座引き落とし等）および既存 DB と重複する行は、初期状態でチェックが外れ、それぞれ適切なバッジが表示されること。
4. 過去に同じ店名で登録した履歴がある場合、次回インポート時にそのカテゴリが自動的に初期選択されること。
5. `npm run verify`（ESLint + TypeScript `tsc --noEmit` + Vitest）がエラー 0 件でパスすること。

## 5. テスト計画（Vitest）

`src/lib/__tests__/amexCsvParser.test.ts` および `src/lib/__tests__/finance.test.ts` に以下を追加する：

* RFC 4180 クォート・カンマ付き金額（`"1,308"`）のパース精度
* 全角英数字・全角スペースの NFKC 正規化とトリム（`Ａｐｐｌｅ ｉＴｕｎｅｓ Ｓｔｏｒｅ ` → `Apple iTunes Store`）
* マイナス金額行のデフォルト除外判定
* キーワード辞書および過去登録履歴に基づくカテゴリ推測
* 重複判定（同一日・同額・同店名がすでに DB にある場合、および同日に同じ店で 2 回決済した場合のカウント整合性）
* 一括登録の DB 永続化検証
